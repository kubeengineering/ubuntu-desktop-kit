# Раскатка с нуля

`bootstrap.sh` нужен один раз — на свежепоставленной системе, где ещё нет ни пакетов, ни расширений, ни шрифтов. Дальше всё делает `design`.

```bash
wget https://raw.githubusercontent.com/kubeengineering/ubuntu-desktop-kit/main/bootstrap.sh
```

```bash
bash bootstrap.sh
```

Пароль спросит один раз, в начале, и только ради установки пакетов. Дальше вопросов не будет.

```bash
bash bootstrap.sh --look night    # другой образ вместо work
bash bootstrap.sh --no-look       # только пакеты, вид не трогать
bash bootstrap.sh --no-walls      # без банка обоев (он долгий на медленной сети)
```

Запускать повторно безопасно: всё уже стоящее пропускается, а не переставляется. Подробности каждой операции пишутся в `~/.cache/ubuntu-kit-bootstrap.log`; в конце скрипт печатает счётчик проблем и что осталось сделать руками.

## Что он делает — и чего принципиально не делает

Раньше bootstrap настраивал внешний вид сам: собирал тему, писал конфиг conky, качал обои, расставлял `gsettings`. Со временем это превратилось во вторую, худшую копию `desktop-kit.sh` — копии разошлись, и одна из них вредила: тема ставилась с флагом `-l`, который подменяет `~/.config/gtk-4.0/gtk.css` симлинком внутрь темы и уносит с собой все наши правки.

Теперь разделение простое. **Bootstrap ставит то, чего в системе нет.** Оформление он передаёт `desktop-kit`, который умеет объяснять и откатывать.

| Шаг | Что происходит |
|---|---|
| Пакеты | около тридцати пакетов из репозиториев плюс PPA Papirus — там живёт `papirus-folders`, которого нет ни в одном выпуске Ubuntu |
| desktop-kit | если bootstrap запущен отдельно от репозитория, скрипт и запускалка `design` скачиваются сами |
| Шрифт | JetBrainsMono Nerd Font с гитхаба: без него значки в виджете будут квадратами |
| pywal16 | палитра, которую `wall` вытаскивает из обоев и раздаёт терминалу |
| Расширения | Dash to Panel, Blur My Shell, Just Perfection, Vitals — ставятся, включаются, `ubuntu-dock` гасится |
| Повадки GNOME | шесть рабочих столов, тап по тачпаду, день недели в часах — поведение, не оформление |
| Обои | `design wallpapers --init` заливает банк |
| Вид | `design themes --install Graphite`, затем `design look work` |
| Клавиши | `design keys --defaults` |
| Погода | `design widget --add weather`, город берётся из переменной `CITY` |

## Две вещи, на которых он спотыкался

**Свежая Ubuntu занимает apt сама.** Первые минуты после установки система тянет обновления через `unattended-upgrade` и держит блокировки. Скрипт в этот момент честно получал отказ и объявлял, что нет сети — хотя сеть была в полном порядке. Теперь он ждёт освобождения очереди и говорит, чего ждёт: молчащий скрипт выглядит зависшим.

**Запуск без терминала.** `sudo` не может спросить пароль, когда его некому спросить, и выдаёт `a terminal is required to read the password` — сообщение, по которому непонятно, что делать. Теперь скрипт проверяет это сам и объясняет по-человечески.

## Чего в нём больше нет

Из набора убраны **rofi** и **gpick** вместе с самодельными меню питания и Wi-Fi. Обе программы X11-нативные, а свежая Ubuntu входит в Wayland: rofi там теряет клавиатуру, пипетка не работает вовсе — Wayland не даёт читать чужие пиксели. Меню питания и список сетей в GNOME есть из коробки, так что дубликаты только путали.

Горячие клавиши тоже переехали. Раньше bootstrap вешал `Super+D`, `Super+R` и прочие — набор из времён, когда меню приложений открывал rofi. Теперь клавиши ставит `design keys --defaults`, и они соответствуют реальности: `Ctrl+Q` — скриншот области, `Ctrl+*` и `Ctrl+/` на цифровом блоке — обои вперёд и назад.

## После запуска

1. **Перелогиньтесь** — расширения, алиасы и панель подхватятся только в новой сессии.
2. Посмотрите, что получилось: `design status`.
3. Не понравился образ — `design look night` или `design look paper`.
4. Совсем назад — `design revert`.

Виджет conky на Wayland иногда не появляется до перезахода: он X11-приложение и стартует раньше, чем поднимается XWayland. Автозапуск это учитывает, но первая сессия после установки бывает капризной.
