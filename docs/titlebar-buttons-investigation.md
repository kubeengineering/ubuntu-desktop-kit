# Кнопки заголовка и углы окон: где остановились

Работа 26.08.2026, **не доведена до конца**. Цель: крупные тонкие кнопки заголовка со **квадратной** подсветкой (красный квадрат на закрытии, серый на остальных) и **острые** углы окон — как в Tabby и в окнах Windows.

Итог на момент остановки: значки заменились, **подсветка осталась круглой, углы окон остались скруглёнными**. Ниже — что установлено достоверно, что перепробовано впустую и что осталось непроверенным.

## Установлено достоверно

**Кнопку рисуют два независимых источника.** Форма значка — крестик, черта, квадрат — берётся из **темы иконок**. Размер кнопки, подложка под значком и подсветка — из **темы GTK**. Правки одного не влияют на другое; это объясняет, почему ранние попытки «менять тему» ничего не давали.

**Papirus не содержит значков заголовка.** В нём есть `16x16/actions/window-close.svg`, но нет `symbolic/actions/window-close-symbolic.svg`, поэтому GNOME подставляет запасные из Adwaita. То есть значки были адвайтовские, а не папирусные.

**Подмена значков работает.** Тема-наследник `ИМЯ-Fluent-Titlebar` с `Inherits=` и четырьмя файлами из Fluent подхватывается: `Gtk.IconTheme.lookup_icon` возвращает пути именно из неё. Проверено на живой машине, в отчёте видно.

**Круглую подложку задаёт Graphite:**

```scss
button.titlebutton:not(.suggested-action):not(.destructive-action) {
  @extend %circular-button;
  min-height: 24px;
  min-width: 24px;
}
```

Три класса в селекторе — специфичность выше обычного пользовательского правила.

**`~/.config/gtk-4.0/gtk.css` — не пользовательский файл.** Установка темы vinceliuice с флагом `-l` заменяет его **симлинком** в каталог темы. Диагностика показала 8693 строки против 88 в GTK3-файле. Всё, что дописывалось «в пользовательский CSS», уезжало внутрь темы.

**Тема Graphite для GTK4 сама сыплет ошибками разбора:**

```
Theme parser error: gtk.css:6866:3-17: No property named "--accent-color"
Theme parser error: gtk.css:6834:15-19: Junk at end of value for background
```

Ошибок больше десятка. Влияют ли они на разбор следующих правил — **не выяснено**.

**Electron не подчиняется ничему из этого.** Chrome, Tabby, Telegram рисуют кнопки сами. Ирония в том, что образцом служит именно Tabby.

## Перепробовано и не сработало

| Что | Результат |
|---|---|
| CSS без `!important` | Тема перебивает по специфичности |
| CSS с `!important` во всех свойствах (26 штук) | Круги остались |
| Раздельные блоки для GTK3 и GTK4 с их собственными селекторами | Без изменений |
| `border-radius: 0` на `decoration`, `window.csd`, `headerbar` | Углы остались скруглёнными |
| Замена симлинка на файл с `@import` темы | Дописано, но до проверки не дошло — откатились раньше |
| `nautilus -q` после применения | Не помогло |

## Не пробовали — отсюда продолжать

**1. Убедиться, что пользовательский CSS вообще читается.** Самая дешёвая проверка, и её пропустили: положить в `~/.config/gtk-3.0/gtk.css` заведомо кричащее правило

```css
window { background-color: red !important; }
```

Если фон окон не покраснел — файл не читается вовсе, и вся возня с селекторами бессмысленна. **Начинать надо было с этого.**

**2. GTK Inspector.** Единственный способ увидеть, какое правило реально применяется к конкретной кнопке:

```bash
GTK_DEBUG=interactive nautilus
```

Вкладка CSS Nodes показывает дерево узлов и победившие правила. Так выяснится и точное имя узла кнопки в GNOME 46, и кто перебивает наш `border-radius`.

**3. Правка самой темы вместо переопределения.** Скопировать `Graphite-Dark` в `Graphite-Dark-Square`, поправить `%circular-button` и радиусы прямо в её файлах, переключиться на копию. Специфичность тогда роли не играет — правило одно. Путь надёжный, но копия отвяжется от обновлений темы.

**4. Пересборка Graphite из исходников.** У install.sh есть `--round` для радиуса (документировано как `2px < value < 16px`, ноль может не приняться) и `--tweaks rimless`. Проверить, что даёт `rimless` — возможно, он и убирает подложку.

**5. Не Snap ли приложения.** Snap-пакеты живут в песочнице и `~/.config/gtk-*` могут не видеть. У пользователя из Snap стоят firefox, thunderbird, telegram-desktop; Nautilus системный, но проверить стоит.

**6. Влияние ошибок разбора темы.** Выяснить, прекращает ли GTK обработку файла после ошибки или продолжает. Если прекращает — наш блок в конце файла просто не доходит до применения, и это объясняло бы всё разом.

## Чего делать не стоит

**Менять тему иконок молча.** Скрипт переключал `icon-theme` на тему-наследника, и со стороны это выглядит как «опять поменяло тему». Даже если папки визуально те же, переключение надо либо объявлять заранее, либо искать способ обойтись без него.

**Менять цветовую схему отдельно от темы GTK.** Один раз это уже дало нечитаемый результат: тема осталась тёмной, схема ушла в светлую, половина окон стала серой кашей.

## Что из этой работы всё-таки пригодилось

- `look.sh` — единый скрипт с частями, откатом, `--check` и `--diag`; механика правильная, упирается только в нерешённый вопрос выше
- Значки Fluent в теме-наследнике — работают, подтверждено инструментом
- `tools/desktop-audit.sh` — снимок системы, которым и нашли симлинк
- Скруглённый conky через Lua и Cairo — сделан, но в этот заход не оценивался
