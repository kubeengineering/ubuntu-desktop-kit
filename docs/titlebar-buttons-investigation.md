# Кнопки заголовка: как это было решено

Задача: крупные тонкие кнопки заголовка с **квадратной** подсветкой (красный квадрат на закрытии, серый на остальных) и настраиваемые углы окон — как в Tabby и в окнах Windows.

**Решено 27.08.2026.** Ниже разбор: что оказалось причиной, какие ложные следы стоили времени и в каком порядке надо было действовать.

## Причина

**GTK не поддерживает `!important`.** Парсер считает его мусором в конце значения и отбрасывает правило целиком:

```
Theme parser error: gtk.css:10:19-20: Junk at end of value for min-width
Theme parser error: gtk.css:14:20-21: Expected a valid color
```

Колонка указывает ровно на `!important`. Все попытки писались верно и в верные места — и выбрасывались на разборе.

Он и не был нужен: `~/.config/gtk-*/gtk.css` грузится с приоритетом `USER`, темы — с `THEME`, который ниже. Пользовательское правило равной специфичности выигрывает само.

## Что ещё выяснилось по дороге

**Круг рисует не кнопка, а её дочерний `image`.** В libadwaita:

```scss
windowcontrols > button > image { background-color: $button_color; border-radius: 100%; padding: 4px; }
windowcontrols > button:hover > image { background-color: $button_hover_color; }
windowcontrols > button { background: none; }
```

Сама кнопка **всегда** без фона. В GTK3 наоборот: Graphite вешает `%circular-button` на кнопку. То есть двум тулкитам нужны разные цели, а не просто разные селекторы.

**libadwaita игнорирует темы**: жёстко ставит `gtk-theme-name` в `Adwaita-empty`. Правка темы — даже её копии — на Nautilus не влияет никак.

**`-gtk-icon-size` есть только в GTK4.** В GTK3 значок растеризуется в 16px, и `-gtk-icon-transform: scale()` растягивает готовый растр: выше ~1.3 появляются пиксели.

**`~/.config/gtk-4.0/gtk.css` часто симлинк** внутрь темы (флаг `-l` у тем vinceliuice). Правки уезжают в тему и теряются при её переустановке.

**GTK3-приложения не перечитывают тему без перезапуска процесса** — `gnome-terminal-server` переживает закрытие всех окон.

**Papirus не содержит `window-*-symbolic`** — GNOME подставляет запасные из Adwaita.

## Ложный след, стоивший нескольких кругов

В тёмной теме кнопки в покое выглядели квадратными, и это было принято за частичный успех. На деле `$button_color` в покое почти совпадает с фоном заголовка, а на наведении цвет светлеет — то есть «квадратно в покое, круг на наведении» это вид **неприменённого** стиля.

Владислав это и поправил: «КРУГИ ПОЯВЛЯЮТСЯ ПРИ НАВЕДЕНИИ». Без этого уточнения перебор селекторов продолжался бы.

## В каком порядке надо было действовать

1. **`GTK_DEBUG=css приложение`** — первым же шагом. Ошибки называют файл, строку и колонку; `!important` нашёлся бы за минуту.
2. Проверить, читается ли пользовательский css вообще — кричащим правилом.
3. И только потом разбираться с селекторами.

Вместо этого несколько кругов ушло на перебор селекторов вслепую, а обе проверки откладывались.

## Что в итоге работает

Правила без `!important` в `~/.config/gtk-3.0/gtk.css` и `gtk-4.0/gtk.css`; прицел в `windowcontrols > button > image` для GTK4 и в `button.titlebutton` для GTK3; значки Fluent через тему-наследник иконок с `Inherits=`; размер значка отдельными параметрами для каждого тулкита; тема GTK и цветовая схема не трогаются вовсе.
