# Что не работает и почему

Список тупиков, проверенных на живой системе. Написан, чтобы не тратить на них время повторно — почти каждый пункт стоил нескольких часов.

## Кнопки заголовка окна не настраиваются

**Хотелось:** крупные плоские кнопки свернуть/развернуть/закрыть, как в Tabby или Telegram, одинаковые во всей системе.

**Почему нельзя.** Каждое приложение рисует заголовок своим способом, и общего места для настройки не существует:

| Тип окна | Кто рисует | Слушается ли тема |
|---|---|---|
| GNOME Terminal и другие с системным заголовком | Mutter | ❌ метрики кнопок берёт свои, не из CSS темы |
| Nautilus, Настройки (GTK4/libadwaita) | libadwaita | ❌ темы GTK игнорирует принципиально |
| Chrome, Tabby, Telegram | сами приложения | ❌ рисуют свои кнопки, о теме не знают |
| Старые GTK3-приложения со своим заголовком | GTK-тема | ✅ единственный случай, где тема работает |

**Что пробовали и что не помогло:** правка `~/.config/gtk-3.0/gtk.css`, правка CSS внутри самой темы, `!important` с точными селекторами темы, темы Fluent / Colloid / Graphite, `gsettings button-layout`. Максимум, чего удалось добиться — кнопки чуть крупнее в GTK-приложениях, плюс паразитные круглые подложки от темы.

**Единственный обходной путь:** пересесть на приложение, которое рисует заголовок само (`gnome-console` вместо GNOME Terminal, Tabby для SSH). Тогда кнопки будут его, а не системные.

## Catppuccin GTK приносит macOS-кнопки

Тема `catppuccin-*-standard+default` собрана на базе Colloid и рисует круглые кнопки в стиле macOS. `gsettings button-layout` на это не влияет — форму задаёт сама тема. Если такой вид не нужен, тему брать не стоит, несмотря на приятную пастельную палитру.

## Тема Tokyo Night не ставится копированием

В репозитории `Fausto-Korpsvart/Tokyo-Night-GTK-Theme` **нет готовых тем** — только исходники. `cp -r themes/*` копирует в `~/.themes` файлы `build.sh`, `install.sh`, `src`, `release`, после чего `gsettings set gtk-theme 'Tokyonight-Dark'` применяет **несуществующее** имя. Ошибки при этом нет: GTK молча откатывается на системную тему, и кажется, что тема стоит.

Тему нужно **собирать** через её же `themes/install.sh -l` (нужен `sassc`), а результат проверять по факту появления каталога, а не по коду возврата `cp`. В `bootstrap.sh` это учтено.

**Как проверить, что реально стоит:**

```bash
gsettings get org.gnome.desktop.interface gtk-theme
ls ~/.themes
```

Если имя из первой команды отсутствует во второй — тема не применена.

## Прозрачность kitty может не работать

На тестовой машине (Ubuntu 24.04, X11, Intel + NVIDIA) kitty не давала прозрачности ни через `background_opacity` в конфиге, ни флагом `-o background_opacity=`, ни с `__GLX_VENDOR_LIBRARY_NAME=mesa`. При этом GNOME Terminal на той же сессии был прозрачным, то есть композитор работал.

Причина не установлена. Kitty рендерит через OpenGL и получает visual иначе, чем GTK-приложения.

Отдельная засада: в Ubuntu 24.04 лежит kitty **0.32**, а плавный курсор (`cursor_trail`) появился только в **0.37** — из apt эту фичу не получить, нужен официальный установщик в домашний каталог. И если старый пакет остаётся в системе, из PATH запускается именно он.

**Вывод:** если нужен только плавный курсор — оно того не стоит. Для прозрачности достаточно GNOME Terminal или Tabby.

## Прозрачность Nautilus — частично

Nautilus 46 написан на libadwaita, который рисует часть поверхностей непрозрачными слоями поверх CSS. Правка `~/.config/gtk-4.0/gtk.css` даёт прозрачным в лучшем случае поле со списком файлов; заголовок и боковая панель остаются плотными.

## papirus-folders нет в apt

Пакета `papirus-folders` **не существует ни в одном выпуске Ubuntu** — `sudo apt install papirus-folders` вернёт «Unable to locate package». Ставится из PPA авторов:

```bash
sudo add-apt-repository -y ppa:papirus/papirus
sudo apt install -y papirus-icon-theme
```

Инструмент подтянется как рекомендованный пакет, а Papirus заодно обновится со сборки 2024 года на свежую.

Дополнительно: красить нужно тему `Papirus` — в `Papirus-Dark` и `Papirus-Light` каталоги иконок это симлинки на неё. И иконки 16×16 в боковой панели Nautilus останутся стоковыми: Catppuccin их просто не рисует.

## Расширение user-theme и gsettings

`gsettings set org.gnome.shell.extensions.user-theme name ...` падает с `No such schema`, если расширение поставлено не из пакета `gnome-shell-extensions`, а с extensions.gnome.org — схема тогда лежит внутри каталога расширения. Рабочий способ, не зависящий от источника:

```bash
dconf write /org/gnome/shell/extensions/user-theme/name "'ИмяТемы'"
```

## Прозрачность панели слетает при смене темы

У Dash to Panel прозрачность включается флагом «использовать своё значение». Если он выключен, панель берёт фон из темы оболочки — и при смене темы внезапно становится непрозрачной. Ключи глобальные, не по мониторам:

```bash
SD=~/.local/share/gnome-shell/extensions/dash-to-panel@jderose9.github.com/schemas
gsettings --schemadir $SD set org.gnome.shell.extensions.dash-to-panel trans-use-custom-opacity true
gsettings --schemadir $SD set org.gnome.shell.extensions.dash-to-panel trans-panel-opacity 0.0
```

При нулевой непрозрачности панель отдаёт литеральное `transparent`, и никакая тема её уже не перекрасит.

## Hyprland не подходит для этой сборки

Видео-гайды по кастомизации в основном показывают Hyprland: толщину рамки, скругление окон, размытие, анимации с кривыми Безье, правила прозрачности для отдельных приложений, экран блокировки с виджетами. Всё это — настройки **Hyprland**, в GNOME их нет.

Hyprland работает только на Wayland и в Ubuntu 24.04 отсутствует в репозиториях (появился в 25.10). Переход на него ломает весь этот набор: conky, rofi, gpick, Dash to Panel, Blur My Shell и остальные расширения GNOME.

Из всего, что показывают в таких гайдах, на GNOME переносятся только курсоры, темы, иконки и утилита [lutgen](https://github.com/ozwaldorf/lutgen-rs) — она перекрашивает **обои под палитру** (обратная задача к pywal, который берёт палитру из обоев).

## Двойной пайп теряется при копировании

Если переносить команды через мессенджер, `||` и `&&` иногда пропадают, и скрипт падает с `syntax error near unexpected token`. Поэтому все скрипты здесь написаны многострочными `if`, без однострочных конструкций вида `[ -f x ] || { ... }`.
