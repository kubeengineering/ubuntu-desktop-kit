# Команды

Один скрипт с подкомандами. Вызывается либо напрямую (`./desktop-kit.sh`), либо через запускалку `design` — она сама держит скрипт свежим.

```bash
design                 список команд
design help buttons    все параметры одной команды
design status          что сейчас применено
design revert          вернуть как было
```

**Команда без аргументов ничего не делает** — она показывает свои параметры и текущие значения. Это сознательно: `design buttons` не должен молча перекрашивать вам окна только потому, что вы решили посмотреть, что он умеет.

| Команда | Что настраивает |
|---|---|
| `look` | весь вид разом: work, night, paper |
| `profile` | снимок оформления целиком и возврат к нему |
| `buttons` | кнопки заголовка: размер, значки, подсветка, цвет закрытия |
| `corners` | скругление углов окон, меню и подсказок |
| `theme` | тема оформления и цветовая схема, в том числе для GTK4-приложений |
| `themes` | банк тем: показать, собрать, проверить на совместимость |
| `icons` | тема значков, цвет папок, банк готовых наборов |
| `font` | шрифт интерфейса и моноширинный |
| `widget` | виджет conky: создать, скруглить, перекрасить, добавить блок |
| `terminal` | GNOME Terminal: прозрачность, шрифт, палитра pywal |
| `panel` | панель задач Dash to Panel: прозрачность, высота, плавающая |
| `newtab` | страница новой вкладки Chrome и её ярлыки |
| `wallpapers` | банк обоев: пополнение, расписание, чистка |
| `wall` | сменить обои: следующие, предыдущие, случайные |
| `keys` | горячие клавиши: показать, добавить, снять |
| `serve` | отдать локальную апку по `http://localhost` |
| `app` | своя тема для одного приложения |
| `tune` | мастер: провести по настройкам и спросить про каждую |
| `refresh` | пересобрать правила, если их снесла установка темы |
| `audit` | полный снимок системы в markdown |
| `status` | что сейчас применено |
| `selftest` | проверить себя на этой машине |
| `revert` | вернуть как было |

Глобальные параметры работают с любой командой: `--dry-run` рассказывает, что было бы сделано, ничего не меняя; `--yes` не переспрашивает; `--quiet` пишет только в лог.

**Каждое изменение обратимо.** Исходное значение запоминается при первом изменении, а не берётся из умолчаний системы, так что `revert` вернёт именно то, что было. Файлы (`gtk.css`, конфиг conky, список ссылок) копируются до первой правки — и копия снимается только с ещё нетронутого файла, иначе повторный запуск сохранил бы уже изменённое.

**Правки не мешают друг другу**: каждая подсистема пишет свой помеченный блок, поэтому `corners` не затирает `buttons`, а чужие правила в `gtk.css` переживают и установку, и откат.

Пополнение банка обоев вешается на расписание этой же командой:

```bash
design wallpapers --timer Wed 13:00
```

Скрипт копирует себя в `~/bin/desktop-kit` и ссылается туда, так что скачанный файл можно потом удалить.

## Внешний вид

### Светлая тема, когда не помнишь её названия

```bash
design theme --light
```

Скрипт берёт тему, которая стоит сейчас, и ищет её парный вариант среди установленных. Слово `Dark`/`Light` может стоять **где угодно** в имени, не только в конце — темы vinceliuice называются `Graphite-Dark-Square`, `Colloid-Dark-Catppuccin`, и это учитывается:

| Стоит сейчас | `--light` даёт |
|---|---|
| `Graphite-Dark` | `Graphite-Light` |
| `Graphite-Dark-Square` | `Graphite-Light-Square` |
| `Colloid-Dark-Catppuccin` | `Colloid-Light-Catppuccin` |
| `Yaru-dark` | `Yaru` |
| `WhiteSur-Darker` | `WhiteSur-Light` |

Знать имя не нужно, `--dark` работает так же в обратную сторону.

Если у выбранной темы нет каталога `gnome-shell`, а оболочка одета в тему другой яркости, скрипт скажет об этом и даст готовую команду `dconf write` — иначе верхняя панель осталась бы тёмной при светлых окнах, и это выглядит как поломка.

Если парного варианта в системе нет, скрипт **не меняет ничего** и показывает список установленных светлых тем. Это сознательно: сменить одну лишь цветовую схему значит получить светлый Nautilus при тёмном терминале — libadwaita слушает схему, а GTK3-приложения тему. Кому нужна именно схема (например, ради GTK4-приложений) — есть `--scheme-only`.

Проверить заранее, получится ли переключиться, можно через `selftest` — он печатает, какие варианты текущей темы есть в системе.

### Установка отсутствующей темы

```bash
design theme --install Graphite-Light
```

Скрипт клонирует репозиторий вендора и собирает нужный вариант. Установщики вендоров называют каталог по-своему (`Graphite-Light`, `Graphite-light`, иногда с суффиксом варианта), поэтому имя не угадывается: список тем снимается до и после сборки, и применяется то, что реально появилось.

### Кнопки заголовка окна

```bash
design buttons                      показать текущие и наборы
design buttons thin                 крупные и тонкие
design buttons --size 36 28 --icon 18
design revert buttons               вернуть как было
```

Кнопку заголовка рисуют **два независимых источника**: форму значка даёт тема значков, размер и подложку — тема GTK. Поэтому правится и то, и другое, иначе получается половина результата — крупная кнопка с мелким значком посередине.

Papirus своих кнопок заголовка не содержит, и GNOME подставляет запасные из Adwaita. Команда создаёт тему-наследника `<база>-dk-glyphs`: она наследует активный набор целиком и переопределяет ровно четыре значка, взятых из Fluent. Папки и приложения остаются прежними, обновление набора правки не затирает, а при смене базы наследник пересобирается сам.

Размер пишется в `~/.config/gtk-3.0/gtk.css` и `gtk-4.0/gtk.css` блоком с маркерами: повторный запуск его заменяет, `--revert` вычищает, а чужие правила в этих файлах не трогаются.

⚠️ На Chrome, Tabby и Telegram не подействует — это Electron, они рисуют кнопки сами.

### Подсистемы не наступают друг другу на ноги

| Что меняешь | Что при этом НЕ меняется |
|---|---|
| `theme` | тема значков, шрифты, цвет папок |
| `icons` | кнопки заголовка — наследник со значками пересобирается поверх новой темы |
| `buttons` | тема значков, выбранная командой `icons` позже |
| `revert theme` | значки и шрифт: у них свои `revert icons` и `revert font` |

Откат теперь по подсистемам: `revert buttons corners theme icons font widget terminal panel newtab app keys serve`. `revert --list` покажет, что запомнено и что можно вернуть.

За темой сами не идут терминал, виджет conky и страница новой вкладки — команда `theme` об этом прямо предупреждает в конце вывода. Для виджета есть `widget --light` и `widget --dark`: они меняют подложку и цвет текста вместе, иначе получается белым по белому.

## Рабочий стол

### Банк обоев

```bash
design wallpapers              # добрать 10
design wallpapers init         # первая заливка, 250 штук
design wallpapers timer        # каждую среду в 13:00
design wallpapers status       # банк, расписание, последние запуски
```

| Команда | Что делает |
|---|---|
| `add 25` | добрать 25 картинок сейчас |
| `init` | первая заливка на чистой системе |
| `timer` | расписание: среда, 13:00, по 10 штук |
| `timer Fri 19:00` | свой день и время |
| `timer Tue,Fri` | дважды в неделю |
| `timer off` | снять расписание, банк и скрипт остаются |
| `status` | сколько картинок, когда следующий запуск, последние запуски |
| `prune 900` | оставить 900 самых свежих (спросит подтверждение) |
| `urls` | показать, какие запросы уйдут на wallhaven |

Качает рисованное — digital art, artwork, illustration и родственные темы — под родное разрешение монитора, определённое через `/sys/class/drm`. Половина запросов идёт случайной выдачей, половина — лучшим за год, поэтому в банк попадает и новое, и проверенное.

Набор тем и seed привязаны к номеру недели: внутри недели повторный запуск даёт ту же выдачу, следующая неделя приносит совсем другую. Уже скачанное не перекачивается, битые файлы и всё тяжелее 12 МБ выбрасывается, страница новой вкладки пересобирается сама.

Среда, а не выходные: рабочий ноутбук включён с понедельника по пятницу, а на выходных `Persistent` просто откладывал бы запуск до понедельника. Пропуск всё равно догоняется — если машина была выключена, пополнение случится при следующем входе.

Расписание ставит скрипт в `~/bin/wallpapers` и ссылается туда, так что скачанный файл можно потом удалить. Каждый запуск пишется в `~/.local/state/wallpapers.log`, по завершении всплывает уведомление.

Первичная заливка на чистой системе — `design wallpapers --init` (~250 штук).

### Смена обоев по порядку

```bash
design wall                       # следующая по списку
design wall --prev                # предыдущая
design wall --random              # случайная
design current      # какая стоит и её номер
```

Листает каталог по порядку — как стрелки на странице новой вкладки, а не «вернуть предыдущую показанную». Позиция запоминается **именем** файла, а не номером: банк пополняется каждую неделю, и номер бы съезжал при появлении новых картинок.

Заодно обновляет палитру pywal, перекрашивает под неё GNOME Terminal и пересобирает страницу новой вкладки, чтобы её фон не совпал с тем, что стоит на рабочем столе.

Ставится на клавиши через `bootstrap.sh`, либо вручную: `setwall` на следующую, `setwall prev` на предыдущую.

## Приложения

### Новая вкладка Chrome

```bash
design newtab
```

Часы, свои ярлыки и обои фоном — причём **не та картинка, что на рабочем столе**. Фон запоминается между вкладками и перезапусками, листается стрелками `←` `→`.

Значки плиток берутся из локального кэша Chrome, поэтому внутренние адреса показываются настоящими иконками, а не заглушкой с буквой. Раз найденный значок запоминается в `icons.json` и больше не теряется, даже если в следующий раз база браузера промолчит.

Ярлыки при первом запуске подтягиваются из самого Chrome (плитки новой вкладки, Top Sites, закладки, история), дальше правятся руками:

```bash
nano ~/.local/share/newtab/links.txt
```

Чтобы страница встала на новую вкладку, нужно расширение — Chrome иначе не даёт. Ставится политикой:

```bash
sudo bash legacy/chrome-policy.sh
```

Подробности, ручной путь и все размеры-шрифты — в [chrome.md](chrome.md). Там же главная грабля: без **Allow access to file URLs** будет белый экран.

Пересобирать после смены обоев или правки ссылок — тем же вызовом `newtab.sh`.

### Локальная апка по http

```bash
design ~/путь/к/апке
```

Плитка с адресом `file://` на новой вкладке молча не открывается: страница живёт в контексте расширения, а Chrome запрещает уходить оттуда к локальным файлам, и «Allow access to file URLs» этого не снимает. Скрипт поднимает апку службой на `127.0.0.1`, убеждается, что она отвечает, и переписывает ссылку в `links.txt` на `http://localhost`.

Из сети апка недоступна — слушается только петлевой адрес.

### Светлая почта при тёмной системе

```bash
design
```

Своей темы у Evolution нет, он берёт системную. Скрипт подставляет `GTK_THEME` в его ярлык — включая пункты контекстного меню дока, иначе «Написать письмо» открывало бы тёмное окно.

### Tabby

[tabby.md](tabby.md) — готовый конфиг прозрачности с плотной панелью вкладок, таблица плотности и разбор трёх ловушек, каждая из которых стоила вечера.

## Сохранить и вернуть

### Профили: сохранить нынешний вид и вернуться к нему

Подобрал тему, значки, шрифт, кнопки, обои — и всё это держится на десятке ключей `gsettings` и паре файлов CSS. Дальше идёшь пробовать новое, что-то ломается, а вернуть прежний вид нечем: `revert` откатывает «как было до нашего первого вмешательства», а не «как было вчера». Профиль закрывает ровно этот пробел.

```bash
design profile save дома      # запомнить, как всё выглядит сейчас
design profile                # список снимков
design profile load дома      # вернуть
```

Имя необязательно: `save` назовёт снимок по дате, `load` без имени возьмёт последний. Перед каждым `load` текущий вид сам сохраняется под именем `before-load`, так что неудачную загрузку можно отыграть назад.

В снимок попадают тема окон и цветовая схема, тема значков, шрифты, курсор, раскладка кнопок заголовка, обои, а также `gtk-3.0/gtk.css` и `gtk-4.0/gtk.css` целиком — то есть наши кнопки и углы возвращаются побайтно. Самих тем и наборов значков внутри нет: они весят гигабайты и лежат отдельно, поэтому запоминаются только имена. Если тему потом снести, `load` честно скажет, чего не хватает, и применит остальное.

### Откат

Полностью убрать всё, что сделал скрипт:

```bash
gsettings reset-recursively org.gnome.desktop.interface
pkill conky
rm -rf ~/.config/conky ~/.config/autostart/conky.desktop
rm -rf ~/bin/{setwall,weather-line,conky-recolor,powermenu,wifimenu,pickcolor,cleanmeta}
rm -rf ~/.cache/wal ~/.cache/wall*
dconf reset -f /org/gnome/settings-daemon/plugins/media-keys/
```

Алиасы — вручную убрать блок `# --- bootstrap aliases ---` из `~/.bashrc`.

Пакеты остаются, они безвредны. Хочешь снести:

```bash
sudo apt purge -y conky-all rofi flameshot lsd bat ranger zathura calcurse gpick mat2
```

### Снимок настроек

```bash
bash tools/desktop-audit.sh
```

Собирает в один markdown-файл всё состояние настроенной машины: версии программ, темы, расширения GNOME вместе с их настройками, горячие клавиши, конфиг Tabby с Custom CSS, расширения и политики Chrome, банк обоев, таймеры, автозапуск, свои скрипты из `~/bin`.

Ничего не меняет, только читает. Значения паролей, ключей и токенов заменяются на `<скрыто>`, так что файл можно пересылать.

Нужен в двух случаях: перенести настройку на новую машину и увидеть, что ещё не автоматизировано — в конце файла сводка «чего не хватает».

## Справка и наследие

### Вся справка разом

```bash
design help --all
```

```bash
design help --settings
```

Первая печатает справку по всем командам подряд, вторая — полный перечень того, что скрипт вообще способен изменить: каждый ключ gsettings и dconf, каждый файл, каждый systemd-юнит, плюс список внешних программ, которые нужны отдельным командам, и раздел «чего скрипт не делает».

### Переход со старых скриптов

`look.sh` и `titlebuttons.sh` (теперь в `legacy/`) писали свои правила блоком `/* look-begin */ … /* look-end */` и заводили тему значков с суффиксом `-Fluent-Titlebar`. `desktop-kit` использует свои маркеры `dk:`, поэтому оба набора могли бы лежать в одном `gtk.css` и спорить за одни и те же селекторы.

Теперь `buttons` находит правила предшественника, спрашивает и снимает их (сделав копию), а `revert` и `icons` понимают тему значков `-Fluent-Titlebar` наравне со своей `-dk-glyphs` — базовая тема из неё восстанавливается корректно. `status` и `selftest` сообщают, если такие правила ещё лежат.

### Старые модули

Предшественники лежат в `legacy/` — рабочие, но замороженные. Всё новое появляется только в `desktop-kit.sh`.
